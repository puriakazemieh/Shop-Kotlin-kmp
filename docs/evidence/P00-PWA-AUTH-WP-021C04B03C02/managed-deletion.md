# حذف امنِ مدیریت‌شدهٔ کاربر

در ۲۰ اکتبر ۲۰۲۶، مسیر حذف عادی WordPress برای حساب‌هایی که metadata `cb_mobile` یا `cb_identity_managed` دارند، در افزونه مسدود شد. مسیر «کارمیلا ← حذف امن حساب» فقط برای مدیر سایت در دسترس است و برای حذف، شناسهٔ عددی حساب، nonce و عبارت تأیید فارسی می‌خواهد.

این مسیر قبل از حذف، وجود پست یا نظر وابسته را بررسی می‌کند و در صورت وجود حتی یکی از آن‌ها بدون نوشتن چیزی حذف را رد می‌کند. برای حساب بدون وابستگی، حذف metadata و سطر کاربر در یک transaction انجام می‌شود؛ پیش از commit، نبودن سطر کاربر با یک پرس‌وجوی مستقیم تأیید می‌شود. در خطا، rollback انجام می‌شود و پنل هیچ پیام موفقیتی نشان نمی‌دهد. رویداد اختصاصی `carmilla_managed_user_deleted` فقط پس از commit اجرا می‌شود؛ callback بومی WordPress پیش از نتیجهٔ transaction اجرا نمی‌شود.

ماتریس disposable با WordPress 6.4.3/PHP 8.1.27، WordPress 6.6.2/PHP 8.2.25 و WordPress 7.1.3/PHP 8.3.35 اجرا شد و این موارد را پاس کرد: مسدودشدن حذف عادی فقط برای حساب مدیریت‌شده، آزادبودن حذف عادی حساب غیرکارمیلا، commit موفق حذف امن، و ردشدن بدون write برای حساب دارای محتوای وابسته. هیچ سایت نگهداری‌شده یا حساب واقعی تغییر نکرد.

## QA دستی لازم

پس از نصب نسخهٔ جدید افزونه روی WordPress آزمایشی، با مدیر سایت به «کارمیلا ← حذف امن حساب» بروید. یک حساب آزمایشی کارمیلا بدون سفارش، پست و نظر بسازید، شناسهٔ آن و عبارت «حذف» را وارد کنید، و بررسی کنید پیام موفقیت نمایش داده شود و حساب دیگر در فهرست کاربران نباشد. سپس یک حساب آزمایشی دارای دادهٔ وابسته را امتحان کنید؛ باید پیام عدم حذف دریافت کنید و حساب همچنان وجود داشته باشد. روی همان حساب کارمیلا در فهرست عادی کاربران، دکمهٔ حذف نباید مجاز باشد. این آزمون را فقط روی حساب آزمایشی انجام دهید.
