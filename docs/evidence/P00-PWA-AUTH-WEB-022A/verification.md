# P00-PWA-AUTH-WEB-022A — bearer scope, partial client hardening

2026-10-18. Status: **AWAITING_MANUAL_QA**, not a complete browser-session implementation or a passed P00 gate. No existing WordPress installation or account was changed. Synthetic tokens were used in tests and their values were not logged here.

## Changes and evidence

- The original JVM HTTP test failed before the fix because a second local server on the same hostname received an Authorization header. The test used disposable in-process servers and a synthetic token, not an external endpoint.
- The common client now scopes automatic bearer sending and 401 reauthorization to the configured origin; a final per-send guard removes Authorization outside the scheme, host, port and API base-path boundary, including Ktor retries and redirects. Encoded/double-encoded path separators or dots and ambiguous traversal paths fail closed. The path-rewrite plugin also requires the same origin. A root API base permits its whole origin by design. This guard strips any explicitly supplied Authorization header outside that boundary as well.
- `:core:network:jvmTest` passed: six tests, including a real local HTTP test proving bearer delivery to the intended endpoint, correct relative `/api/` rewriting, no header to a different local port or host after 401 challenges, and no header on redirects outside the path or to a different port. URL unit checks cover scheme, port, hostname, path boundary and encoded traversal. These tests are not HTTPS, Android, iOS, WordPress or production integration tests.
- Fetch for the JS client now fails closed on automatic redirects, because browser-managed redirects can bypass Ktor's per-send hook. **All browser network requests through this client, including Spring, now reject redirects**, even same-origin safe ones. Backends must expose final URLs directly; compatibility with actual Spring and WordPress deployments must be tested before release. Bootstrap fetches outside this client are not covered. Explicit per-request FetchOptions could override the engine default; none are currently used in this module. Cookies and full web-session CSRF protections are outside this card.
- `:core:network:jsBrowserTest` passed two tests in Chrome Headless 153 on Windows; the added test substitutes Fetch with a synthetic response and observes `redirect=error` and `credentials=include` from the real compiled Ktor JS client. It does not test actual redirect network behavior or a live login. The first run failed before execution because generated `skiko.mjs` was missing. For the second run, missing `skiko.mjs` and `skiko.wasm` were copied, without overwrite, from the already generated `build/js/packages/kmp-shop-core-data-test/kotlin/` into `build/js/packages/kmp-shop-core-network-test/kotlin/`. This is a local generated-output workaround, not a durable build fix.
- `:composeApp:compileKotlinJs :composeApp:compileKotlinJvm` succeeded. `:core:network:compileAndroidMain --offline` failed before compilation because the configured `androidx.annotation:annotation-experimental:1.4.0` AAR was not in the local cache. iOS was not built on this Windows host. Android/iOS behavior remains unverified.
