## Reasons

- **FIX-1:** `class-cb-auth-controller.php:95-110` passes `WP_Error::get_error_message()` from a filter or SMS adapter to an exception; `:155-160` returns that exception text through `cb_error`, whose implementation in `includes/helpers.php:22-33` places it in a public REST JSON response. JSON encoding handles markup context, but a provider or filter may include internal endpoint/account details. Create `P02-SEC-CODE-010C2B1A` to return a generic public error while preserving a safe operational diagnostic.
- **CTX-1:** `class-cb-local-qa-otp-sink.php:9-10,25-44` is disabled off localhost, requires admin capability and nonce before reading a transient, and escapes the mobile when rendered. The raw mobile only selects an MD5-derived transient key; it is not SQL, HTML, or a provider destination. Validation hardening may be useful, but this finding does not show an exploitable unsanitized sink.
- **CTX-2:** `class-cb-otp-atomic-consumer.php:13-43` and `class-cb-reset-atomic-consumer.php:8-31` use `$wpdb->prepare` for values, compare the exact stored value and expiry in one DELETE, and bypass cache for one-time consumption. Caching would undermine the atomic guarantee.
- **CTX-3:** `class-cb-web-auth-controller.php:15-30` checks a live schema version with a constant SELECT after `CB_Web_Session_WP_Adapter::from_wordpress()` validates the installation and prefix; stale cached schema state would be unsafe.
- **CTX-4:** `class-cb-web-auth-controller.php:93-105` forwards server IP/TLS/host metadata to `CB_Web_Request_Policy::transport_ok`, which validates IP types, compares the canonical host with the configured origin, and requires TLS or a strict local QA exception (`class-cb-web-request-policy.php:114-140,161-168`). The values are not output or interpolated in SQL.
- **CTX-5:** `class-cb-web-auth-controller.php:108-110` passes the cookie byte-for-byte to the session store. `class-cb-web-session-store.php:226-227` requires a 64-character lowercase hex credential before hashing it; `rotate`/`revoke` use the digest. Generic text sanitization could alter a credential and is not the appropriate validation.
- **CTX-6:** `class-cb-web-auth-login.php:86-105` uses `$wpdb->prepare` at :95 before `$wpdb->get_col($sql)` at :96. The query checks ambiguous identifiers across login, email and mobile; live lookup is required for auth and must not be cached. The `NotPrepared` sniff misses the prepared assignment.
- **CTX-7:** `class-cb-web-session-wp-adapter.php:53-57` uses constant `SELECT DATABASE()` / `SELECT CONNECTION_ID()` to verify the active database and connection at runtime. Caching would defeat this identity check.
- **CTX-8:** `class-cb-web-session-wp-adapter.php:19-77,117-159` permits only a local DB host and standard `wpdb`, rejects drop-ins/multisite/custom user tables, verifies same primary via `information_schema`, and creates separate autocommit mysqli connections for the isolated session store. `mysqli_init` is intentional here and errors fail closed.
