# Email password-reset handler — limited synthetic verification

2026-10-20. The Bridge reset handler no longer creates a separate WordPress reset key. It observes the single key generated by `retrieve_password`, stores only a SHA-256-derived transient lookup for that emailed key, validates it with WordPress core, atomically consumes the mapping, resets the password, and revokes existing JWTs. A successful reset returns `{ "reset": true }`, not credentials.

The disposable test passed on WordPress 6.4.3/PHP 8.1.27, WordPress 6.6.2/PHP 8.2.25, and WordPress 7.1.3/PHP 8.3.35. It verifies generic unknown-email behavior, the emailed-key mapping, native core key validation, a successful reset without tokens, and rejected replay.

No actual email was delivered; mail was intercepted in the test. No retained site, user, reset key, credential, token, or public deployment was involved. Persistent external object-cache mode remains unsupported and must fail closed for Bridge email-reset mapping.
