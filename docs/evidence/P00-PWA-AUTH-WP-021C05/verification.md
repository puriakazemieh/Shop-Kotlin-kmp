# P00-PWA-AUTH-WP-021C05 — isolated handler verification

2026-10-25. The Bridge reset handler observes the single key generated by `retrieve_password`, stores only a SHA-256-derived transient lookup for that emailed key, validates it with WordPress core, atomically consumes the mapping, resets the password, and revokes existing JWTs. A successful reset returns `{ "reset": true }`, not credentials.

Fresh disposable WordPress 6.4.3/PHP 8.1.27 checks passed for both components:

- `smoke-web-refresh-logout-real-wp.php`: 17/17 checks. It covers origin/method/CSRF rejection before mutation, missing/unknown/expired credentials, atomic refresh rotation, opaque-cookie redaction and flags, replay revocation of only one family, logout/idempotency, password-change invalidation, signing and storage failures, and mismatched wiring.
- `characterize-email-reset-real-wp.php`: reset lifecycle checks passed after its synthetic identity fixture. It covers generic unknown email, one actual WordPress emailed key, core validation, one-time consume/replay rejection, and a credential-free success response.
- Docker PHP lint passed for `class-cb-web-auth-session.php`, `class-cb-auth-controller.php`, `class-cb-reset-atomic-consumer.php`, and both fixtures.

No actual email was delivered; mail was intercepted in the test. No retained site, user, reset key, credential, token, route registration, or public deployment was involved. Persistent external object-cache mode remains unsupported and must fail closed for Bridge email-reset mapping. Network activation and browser QA are explicitly deferred to `P00-PWA-AUTH-WP-021C07`.
