## Reasons

- **CTX-1:** `class-cb-academy-controller.php:59-62` registers project upload as an authenticated REST POST with `CB_Plugin::require_login`. WordPress REST cookie authentication enforces its nonce before the callback; bearer-token clients use their own authentication. At :650-662, `media_handle_upload` receives the file only after that permission gate. The WPCS nonce warning sees raw `$_FILES` but not the route authentication.
- **FIX-1:** `class-cb-clinic-controller.php:86-90` builds `$table` only from trusted `$wpdb->prefix` via `cb_bookings_table()` (`includes/helpers.php:540-543`) and prepares the therapist ID. The SQL interpolation itself is not request injection. However a failed live `get_col` is converted to an empty booked-slot list, so the availability response can falsely advertise all slots. Queue `P02-SEC-CODE-010C2B3A1` to fail closed on DB read failure. Caching would be unsafe for current booking availability.
- **FIX-2:** `class-cb-clinic-controller.php:218-246` uses prepared values and a unique `(therapist_id,slot_time)` key for the live lock. After the lock insert, `wp_insert_post`, metadata writes and the lock-row update are not checked or compensated on failure; an orphan lock or incomplete appointment may be reported. Queue bounded characterization and repair `P02-SEC-CODE-010C2B3A2`. The WPCS table interpolation is trusted-prefix SQL, not itself injection.
- **FIX-3:** `class-cb-clinic-controller.php:249-263` marks a CPT appointment CANCELLED and then ignores `$wpdb->delete` failure for the lock row. A failed delete leaves the slot blocked while the API reports success. Queue `P02-SEC-CODE-010C2B3A3`.
- **PERF-1:** `class-cb-academy-controller.php:719-733`, `class-cb-clinic-controller.php:266-281,401-420,450-459` and `class-cb-admin-clinic-controller.php:172-180` use WordPress comment/post meta filters. `post_id` bounds the comment searches, and the appointment list has a 100-result limit; nevertheless `meta_value` is not normally indexed and the total scanned rows may grow. No query plan or realistic cardinality measurement is present, so these ten warnings are unresolved performance reviews, not proven security defects or automatic waivers. Queue academy `P02-PERF-REVIEW-010C2B3B1`, clinic `P02-PERF-REVIEW-010C2B3B2` and admin clinic `P02-PERF-REVIEW-010C2B3B3` to measure and create fixes for material slow paths before C2C.
