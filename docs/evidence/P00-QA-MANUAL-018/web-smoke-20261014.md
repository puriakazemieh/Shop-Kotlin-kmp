## 2026-10-17 PWA login blocker

- The owner reported an unknown-error banner on PWA login; P00-T05 has not passed.
- The deployed JS bundle selects `api/auth/web/login` for browser login. A direct POST to the configured local WordPress REST API returned HTTP 404 (`rest_no_route`) for that route; the non-web `api/auth/login` returned HTTP 200 for the synthetic account. The earlier HTTP 200 therefore did not establish that PWA login works.
- Security concern: the current JS token-settings factory returns browser settings backed by `localStorage`, and the current dependency-injection binding supplies the general settings to `TokenManager`. This conflicts with the in-memory web-token contract stated in `P01-SECURITY-CODE-005C`; simply redirecting web login to the non-web endpoint would expose the refresh token to persistent browser storage.
- Required follow-up: align the WordPress browser-session endpoints and client-side token storage with the intended security contract, then verify login, refresh, logout and storage behavior in a real browser. Preserve the WordPress test sites and their data.
