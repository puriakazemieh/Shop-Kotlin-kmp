# P00-PWA-AUTH-WP-021C04B03C01 — آزمایش مرجع مشترک مصنوعی

تاریخ اجرا: ۲۰۲۶-۱۰-۱۸. محدوده این شاهد فقط یک نمونه تحقیقاتی، موقتی و ترتیبی است؛ محافظت محصول یا مجوز مهاجرت نیست.

## محیط و روش

- MariaDB `10.6.28` در کانتینر مجزا با storage موقت؛ بدون پورت منتشرشده، بدون mount پایگاه‌داده یا وردپرس کاربر. هر اجرا prefix تصادفی مختص خود داشت و ارتباط در namespace همان کانتینر برقرار بود.
- WordPress واقعی `6.4.3` / PHP `8.1.27`، `6.6.2` / PHP `8.2.25` و `7.1.3` / PHP `8.3.35`، با جدول‌های `users` و `usermeta` از نوع InnoDB؛ هر سه اجرای کامل با exit code صفر پایان یافتند.
- اسکریپت [experiment-identity-shared-references.php](../../../wordpress/carmilla-bridge/tests/experiment-identity-shared-references.php) تنها با flag صریح disposable، نام پایگاه‌داده مصنوعی ثابت و prefix تصادفی اعتبارسنجی‌شده اجرا می‌شود. `php -l` پاس شد و اجرای بدون flag/prefix پیش از اتصال رد شد. نام‌ها و آدرس‌های fixture ساختگی‌اند و هیچ ایمیلی ارسال نمی‌شود.
- پس از `wp_install`، دو جدول آزمایشی InnoDB، procedure و trigger در همان prefix ساخته می‌شوند. admin ساخته‌شده هنگام نصب عمداً backfill نشده است؛ این آزمایش نصب روی سایت موجود را پوشش نمی‌دهد. داده، لاگین، مسیرها، افزونه‌ها و schema سایت‌های وردپرس نگه‌داری‌شده کاربر تغییر نکرده‌اند.

## نتیجه قابل بازبینی

در هر سه ترکیب بالا تمام assertionهای زیر PASS شدند:

1. یک claim باینری مشترک با مراجع مستقل login و دو ردیف `cb_mobile` متعلق به همان کاربر ایجاد شد؛ پس از تغییر login هر دو مرجع موبایل و مالکیت قبلی باقی ماندند. مالک متفاوت نتوانست همان مقدار را با INSERT مستقیم تصاحب کند.
2. حذف یک مرجع با `delete_metadata_by_mid` claim را نگه داشت؛ تغییر آخرین مرجع با `update_metadata_by_mid` فقط claim بدون مرجع را آزاد کرد.
3. INSERT، UPDATE و DELETE مستقیم `usermeta` و نیز `update_user_meta` و `delete_user_meta` برای چند ردیف تکراری، تعداد مراجع و مالکیت مورد انتظار را حفظ کردند. حذف آخرین مرجع claim را آزاد کرد.
4. login و email یکسان برای همان کاربر دو مرجع یک claim داشتند؛ `wp_update_user` ایمیل را تغییر داد ولی claim مربوط به login را نگه داشت.
5. `billing_phone` مستقل از claim باقی ماند؛ مقدارهای خالی، کوتاه، غیرعددی و NULL برای موبایل مصنوعی رد شدند. UPDATE ناسازگار با مالک دیگر یا مقدار نامعتبر، مرجع قبلی را حفظ کرد. ROLLBACK تراکنش حذف metadata نیز مرجع قبلی را برگرداند.
6. DELETE مستقیم کاربر با `cb_mobile` موجود fail-closed شد؛ پس از حذف metadata، DELETE مستقیم user مراجع باقیمانده را آزاد کرد. `wp_delete_user` نیز برای یک کاربر مصنوعی با metadata، ابتدا metadata و سپس claimهای آخر را پاک کرد.

## محدودیت‌ها و گام بعد

- این مدل فقط مقایسه دقیق بایت‌ها و مقادیر مصنوعی `cb_mobile` شامل دقیقاً ۱۱ رقم ASCII را می‌پذیرد؛ این شرط، اعتبارسنجی شماره ایران یا سیاست نرمال‌سازی محصول نیست. تفاوت حروف/فاصله کلید meta و collation، encodingهای دیگر، aliasهای غیرنمونه و migration/backfill داده موجود پوشش ندارند. داده‌هایی مانند Unicode یا رشته‌های سریال‌شده پشتیبانی یا برای محصول معتبر فرض نشده‌اند.
- نتیجه ترتیبی، ایمنی هم‌زمانی، ترتیب lock، deadlock، تغییر مالک metadata، تداخل نویسندگان، یا رفتار همه افزونه‌ها و hookها را اثبات نمی‌کند. `P00-PWA-AUTH-WP-021C04B03C02` برای همین بررسی‌هاست. هیچ اثری از برگشت‌پذیری side effect خارجی یا حفاظت OTP نتیجه‌گیری نشده است.
- یافته‌های قبلی درباره بازگشت شناسه ظاهراً موفق و اجرای hook وردپرس پس از خطای database همچنان باز هستند. این شاهد اعلام نمی‌کند ورود یا ثبت‌نام PWA روی سایت واقعی درست شده است.
