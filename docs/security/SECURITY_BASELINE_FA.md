# بیس‌لاین امنیتی و طبقه‌بندی داده‌ها (Security Baseline)

> نسخه سند: ۱.۰  
> تاریخ: ۵ اوت ۲۰۲۶  
> وضعیت: پیش‌نویس (Task P00-SECURITY-DISC-013)

این مستند چارچوب حفاظتی داده‌ها و دارایی‌های دیجیتال پروژه Carmilla را تعریف می‌کند.

---

## ۱. طبقه‌بندی داده‌ها (Data Classification)

| سطح حساسیت | نمونه داده‌ها | الزامات حفاظتی |
|---|---|---|
| **Public** | کاتالوگ محصولات، مقالات وبلاگ، نام متخصصین | بدون محدودیت انتشار. |
| **Internal** | لاگ‌های بیلد، متادیتای ادمین، ساختار مانیفست | دسترسی محدود به تیم فنی. |
| **PII (Personal)** | نام، ایمیل، شماره موبایل، آدرس مشتری | رمزنگاری در پایگاه داده، دسترسی بر اساس نیاز. |
| **Financial** | تراکنش‌های پرداخت، سوابق کیف پول، کدهای تخفیف | رمزنگاری قوی، عدم ثبت در لاگ‌های عمومی. |
| **Health (Sensitive)**| نتایج تست روان‌شناسی، یادداشت‌های درمانی | تفکیک فیزیکی یا منطقی، رمزنگاری در سطح اپلیکیشن (Application Level). |
| **Secret** | کلیدهای JWT، API Keyها، رمزهای عبور | نگهداری در Vault، چرخش (Rotation) دوره‌ای. |

---

## ۲. نگهداری داده‌ها (Retention Policy)
- **لاگ‌های دسترسی**: ۶ ماه.
- **سوابق مالی**: ۵ سال (طبق قوانین مالیاتی).
- **داده‌های سلامت**: طبق توافق‌نامه مراجع و مشاور (حداقل ۲ سال پس از آخرین مراجعه).
- **داده‌های حذف شده**: پاکسازی فیزیکی پس از ۳۰ روز از سطل زباله منطقی (Soft Delete).

---

## ۳. سطوح تهدید (Threat Surfaces)
1. **API Endpoints**: تهدیدهای نفوذ، IDOR و حملات DoS.
2. **Web/PWA**: حملات XSS، CSRF و سرقت توکن از Local Storage.
3. **Android App**: مهندسی معکوس، دسترسی به توکن در صورت روت بودن دستگاه.
4. **WordPress Theme**: نفوذ از طریق فایل‌های PHP پوسته (Plugin Territory).
5. **Spring Backend**: دسترسی غیرمجاز به دیتابیس PostgreSQL.

---

## ۴. فهرست اسرار (Secret Inventory - Metadata)
*توجه: هیچ مقدار واقعی (Value) در این جدول ثبت نمی‌شود.*

| شناسه | نوع | محل نگهداری (هدف) | چرخش (Rotation) |
|---|---|---|---|
| `JWT_SECRET` | Signing Key | Env / Vault (Spring & WP) | هر ۹۰ روز |
| `DB_PASSWORD` | Credential | Env / Docker Secret | سالانه |
| `SMS_API_KEY` | API Key | WP Options (Encrypted) | در صورت نشت |
| `GATEWAY_TOKEN`| Auth Token | WP Options (Encrypted) | در صورت نشت |
| `SIGNING_KEY` | JKS/P12 | External Vault (Android/iOS) | سالانه |

---

## ۵. الزامات عمومی
- استفاده از پروتکل **HTTPS** برای تمامی ارتباطات اجباری است.
- هیچ داده حساسی (PII/Financial) نباید در Headerهای HTTP یا Query String ارسال شود.
- تمامی ورودی‌های کاربر باید سمت سرور (Sanitize & Validate) شوند.
