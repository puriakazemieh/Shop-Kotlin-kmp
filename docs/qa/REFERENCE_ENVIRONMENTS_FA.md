## ۲. ماتریس نرم‌افزاری (Software Stack)

### ۲.۱ زیرساخت وردپرس (WordPress Path)
- **OS**: Linux (Alpine/Debian via Docker)
- **PHP**: `8.1` (Minimum: 7.4)
- **WordPress**: `6.4` یا بالاتر
- **WooCommerce**: `8.5` یا بالاتر (با فعال بودن HPOS)
- **Database**: MariaDB `10.6`

### ۲.۲ زیرساخت اسپرینگ (Spring Path)
- **Java**: `21` (Temurin/OpenJDK)
- **Database**: PostgreSQL `15`
- **Container**: Docker `24+`

## ۴. روش بازنشانی محیط (Environment Reset)

برای اطمینان از صحت تست‌ها، فقط محیط آزمایشی مجزا و قابل‌دورریختن با هدف و داده‌های مشخص را طبق روش‌های زیر به حالت پاک بازگردانید. سایت‌های WordPress نگهداری‌شده، پایگاه‌داده‌ها و volumeهای آن‌ها را حفظ کنید؛ این دستورها مجوز حذف یا بازنشانی آن‌ها نیستند.

1. **WordPress**: در صورت نیاز محیط پاک جداگانه بسازید. `docker-compose down -v` می‌تواند volumeها و داده‌ها را حذف کند و برای محیط‌های نگهداری‌شده ممنوع است؛ درباره محیط موقت نیز ابتدا هدف و امکان بازیابی داده‌ها باید مشخص باشد.
2. **KMP Client**: فقط Cache و Local Storage پروفایل آزمایشی مشخص را در صورت نیاز پاک کنید.
3. **Database**: اسکریپت‌های مرجع `db/init` فقط در پایگاه‌داده آزمایشی مجزا و پس از بررسی هدف استفاده شوند؛ بازنویسی پایگاه‌داده موجود مجاز نیست.
